### “Debugging the tester’s day: common problems and powerful solutions”

[Sanjay Kumar](https://www.linkedin.com/in/creator-sanjaykumar/)

**Abstract/description**

Traditional testing methodologies often lead to repetitive and time-consuming tasks, creating an atmosphere where testing is perceived as monotonous. Throughout the testing process, from learning and reading to exploratory/manual testing, bug filing, bug reproduction, automation testing, locators writing, code writing, data generation, links testing, performance testing and career growth, there are numerous opportunities for innovation. Join us in this talk as we address the common challenges faced by testers in their daily routines and present practical, innovative solutions. Discover how embracing creativity at every stage of testing can not only make the process more interesting but also significantly reduce the time spent on tedious tasks. Walk away with actionable insights with free solutions/tools that you can immediately apply to enhance your daily testing practices.

**Outline**

I will first talk about the tester's daily regular practice problems with examples and then solution for those problems.

1. I will talk about the problems to test links, performance of websites, data generation then will present the solution for these problems.
2. Problems while doing exploratory testing, bug reproduction, bug filing then solution for these.
3. The problems in DOM learning, locators writing, xpath learning etc and then solution for it with real time examples.
4. Problems like keeping yourself updated with latest testing trends, events etc then will show solutions for this.

**Takeaways**

1. Attendees will be saving at least 40-50% time which is spent today in writing test cases, filing bugs, writing automation scripts and locators, testing links, testing performance of the website without compromising learning skills.
2. Learn how we should use automation tools without compromising learning skills.
3. Know about the solution to maintain your automation script whenever a UI change happens.
4. Learn to find the broken links, testing all kinds of links without writing code.
5. Learn to test the performance of your application without any effort.
6. Learn how innovatively you can learn more about the DOM, locators, xpath and different kinds of complex web elements without doing anything extra from your regular practices.
